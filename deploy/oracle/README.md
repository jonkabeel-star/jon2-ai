# Jon2 AI — Oracle Cloud ARM64 deployment

This is the persistent CPU-serving path for the independent Jon2 project. It
does not use Render, a temporary notebook URL, or a hosted AI inference API.

## Architecture

- GitHub Pages continues to host the static website.
- An Oracle Cloud Ampere A1 ARM64 VM runs the local API and llama.cpp.
- The API loads a privately stored Qwen3.5-2B GGUF file from
  `/opt/jon2/models`.
- The browser calls the API over HTTPS. The API calls the local llama.cpp
  process over loopback only.
- The original 269,952-parameter Jon2 prototype remains preserved for research;
  it is not used as the public assistant because its Arabic output failed the
  held-out quality review.

Oracle currently documents 1,500 OCPU-hours and 9,000 GB-hours per month for
Always Free A1, equivalent to 2 OCPUs and 12 GB RAM when continuously allocated.
Capacity is not guaranteed in every home region, and the VM is CPU-only. See
https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm

## Model choice

The practical training target is `Qwen/Qwen3.5-2B` (Apache-2.0), not the much
larger Qwen3.8-27B. The 2B checkpoint is a 4.57 GB download and is intended
for task-specific fine-tuning and research. Unsloth documents 16-bit LoRA
fine-tuning for the Qwen3.5 small family; it recommends avoiding 4-bit QLoRA
for this architecture. The first training run exports a Q4_K_M GGUF for CPU
serving. The exact export must be tested on the target ARM VM before release.

References:
- https://huggingface.co/Qwen/Qwen3.5-2B
- https://unsloth.ai/docs/models/qwen3.5/fine-tune
- https://github.com/ggml-org/llama.cpp

## VM preparation

Create an Ubuntu 24.04 ARM64 VM in the Oracle home region. Select only resources
labelled Always Free and keep within the documented 2 OCPU / 12 GB memory
monthly allowance. Do not enable paid resources or change the account to a
paid service for this guide. Oracle may report temporary out-of-capacity errors.

Create a persistent directory on the VM:

```bash
sudo mkdir -p /opt/jon2/models
sudo chown -R "$USER":"$USER" /opt/jon2
```

Copy the privately generated GGUF file into that directory using a secure
transfer method. Do not commit model weights, adapters, training data, or
credentials to GitHub. Expected filename:

```
/opt/jon2/models/jon2-qwen35-2b-q4_k_m.gguf
```

## Build and start the API

From a clone of the repository on the VM:

```bash
docker compose -f docker-compose.oracle.yml build
docker compose -f docker-compose.oracle.yml up -d
```

The API is intentionally bound to loopback on port 8000. Put Caddy or another
HTTPS reverse proxy in front of it; do not expose port 8000 directly to the
public internet. Configure DNS for a domain pointing to the VM and use
`deploy/oracle/Caddyfile` as the reverse-proxy site block.

Set these environment variables only after the model has been tested privately:
- `JON2_ALLOWED_ORIGINS=https://jonkabeel-star.github.io`
- `JON2_CHAT_RELEASE_APPROVED=false` during initial deployment.
- `JON2_GGUF_PATH=/models/jon2-qwen35-2b-q4_k_m.gguf`

## Verification

```bash
curl -fsS https://YOUR_DOMAIN/api/health/live
curl -fsS https://YOUR_DOMAIN/api/health
curl -i https://YOUR_DOMAIN/api/health/ready
```

A live API is not proof that the model is ready. Before release:
1. Verify `model_file_present`, `model_process_running`, and `chat_ready`.
2. Run the held-out Arabic benchmark against the exact GGUF.
3. Compare base and adapter outputs on identical prompts.
4. Human-review Egyptian Arabic and Modern Standard Arabic for correctness,
   relevance, repetition, privacy leakage, and unsupported claims.
5. Confirm memory use and response latency on the actual 2 OCPU / 12 GB VM.
6. Only then set `JON2_CHAT_RELEASE_APPROVED=true` and restart the service.

The current training data approvals authorize private experimental research
only. They do not authorize commercial use or public redistribution. Do not
publish the trained adapter or GGUF without a separate rights review.

## Important limits

- This repository change prepares the deployable service; it does not create
  an Oracle account, VM, public IP, DNS record, or TLS certificate.
- The current Qwen adapter has not yet been trained. The model GGUF file must
  be generated by the GPU training workflow and securely copied to the VM.
- CPU inference on 2 OCPUs will be slow. Measure actual latency before opening
  public access. Oracle Always Free availability and capacity are not guaranteed.
