# تشغيل Jon2 AI مجانًا على Kaggle GPU — دليل المالك

هذا الدليل يشرح مسارًا مجانيًا قدر الإمكان لتشغيل **فحوصات البيانات والتدريب التجريبي للنموذج الأصلي Jon2** على Kaggle، مع إدارة المشروع من iPhone عبر Safari. لا ينشئ خادمًا دائمًا ولا يضمن توافر GPU أو حصة مجانية في كل وقت.

## حدود مهمة قبل البدء

- GitHub Pages يستضيف واجهة الموقع فقط؛ لا يشغّل PyTorch أو النموذج.
- Kaggle Notebooks قد توفر GPU مجانيًا بحسب أهلية الحساب والحصة والتوافر. الجلسات مؤقتة وقد تنقطع.
- GitHub Actions العادية لا تعني وجود GPU. استخدمها لاختبارات الكود والتحقق فقط.
- لا ترفع checkpoint خاصًا أو بيانات تدريب خاصة أو مفاتيح API إلى GitHub.
- لا تشغّل تدريبًا على مصدر لم تتم الموافقة على حقوقه واستخدامه المقصود في سجل الموافقات الخاص.
- لا تستخدم أسئلة مجموعة الاختبار المحجوزة في التدريب.
- لا تفتح محادثة الموقع ولا تغيّر بوابة الإصدار لمجرد أن التدريب أو تحميل checkpoint نجح.

## الحالة المعروفة للمشروع

آخر فحوصات المشروع أظهرت أن checkpoint الأصلي يمكن تحميله وتشغيله تقنيًا، لكن الردود العربية كانت غير مفهومة. لذلك يظل إطلاق المحادثة العامة محظورًا إلى أن ينجح تقييم عربي محجوز ومراجعة بشرية.

مصادر مثل ArabicText-Large وHPLT غير معتمدة حاليًا للاستخدام التدريبي المقصود. ملفات الحوارات الأصلية المسجلة كمسودات تحتاج مراجعة المالك وموافقة صريحة على الملف المحدد واستخدامه. لا تعتبر وجود الملف في المستودع موافقة تدريب.

## أ) تجهيز Kaggle من iPhone

1. افتح https://www.kaggle.com/ وسجّل الدخول.
2. افتح صفحة Code ثم اختر New Notebook.
3. من إعدادات Notebook اختر Accelerator: GPU إذا ظهر وكان متاحًا لحسابك.
4. ابدأ أولًا بفحص البيئة فقط؛ لا تبدأ التدريب.
5. إذا كانت بياناتك أو checkpoint في Kaggle Private Dataset، أضفها إلى Notebook من لوحة Add Input، وتأكد أن اسم المجموعة والملفات هي المقصودة.
6. لا تجعل أي Dataset خاصًا عامًا، ولا تضع مفاتيح Kaggle أو GitHub داخل خلية Notebook أو ملف محفوظ في GitHub.

## ب) فحص GPU قبل أي تدريب

شغّل هذه الخلية في Kaggle. هي فحص فقط ولا تحمل بيانات ولا تغيّر checkpoint:

```python
import os
import platform

print("Python:", platform.python_version())
print("Platform:", platform.platform())

try:
    import torch
    print("PyTorch:", torch.__version__)
    print("CUDA available:", torch.cuda.is_available())
    if torch.cuda.is_available():
        print("GPU:", torch.cuda.get_device_name(0))
        print("CUDA:", torch.version.cuda)
        print("GPU count:", torch.cuda.device_count())
    else:
        print("STOP: No GPU is attached. Do not start a GPU training run.")
except Exception as exc:
    print("PyTorch check failed:", repr(exc))
```

إذا كانت `CUDA available: False`، توقف ولا تعتبر الجلسة GPU.

## ج) تدقيق الملفات قبل التدريب

1. أضف فقط مجموعة البيانات الخاصة التي تملكها أو لديها إذن موثق للاستخدام التدريبي المحدد.
2. تحقق من وجود سجل موافقة خاص يطابق الملف نفسه عبر SHA-256 وعدد الأحرف ونطاق الاستخدام.
3. افصل بيانات التدريب عن بيانات التقييم المحجوزة على مستوى المصدر/المحادثة، لا على مستوى السطر فقط.
4. شغّل تدقيق البيانات ومرحلة preflight الموجودة في مستودع Jon2 قبل التدريب.
5. إذا ظهرت أسباب BLOCKED مثل نقص الحجم أو غياب موافقة مصدر، توقف. لا تخفض الحدود ولا تعِد تدوير النصوص أو تكررها لتجاوزها.

## د) التدريب والاستئناف

بعد أن تصبح مجموعة البيانات معتمدة فعلًا ويعطي preflight نتيجة تسمح بالتدريب:

- استخدم مسار التدريب الأصلي الموجود في `ai_engine/train_jon2.py`، وليس خدمة AI خارجية.
- ابدأ بإعداد صغير مناسب لذاكرة GPU المتاحة، ولا تنتقل إلى نموذج أكبر لمجرد أن GPU ظهر.
- احفظ checkpoint جديدًا في `/kaggle/working/` ولا تستبدل checkpoint المصدر.
- فعّل حفظ آخر حالة تدريب (last/resume checkpoint) بحيث تشمل حالة optimizer وscheduler وRNG وبيانات الخطة وبصمة corpus.
- بعد انتهاء الجلسة، نزّل ملفات الناتج الخاصة أو احفظها في Kaggle Private Dataset؛ لا ترفعها إلى GitHub أو إلى Dataset عام.
- احسب SHA-256 للملفات الناتجة وسجّلها مع إعدادات التدريب ومصدر البيانات وبصمته.

**مهم:** لا يوجد في هذا الدليل أمر تدريب جاهز للتشغيل الآن، لأن المصادر المتاحة في سجل المشروع ليست كلها معتمدة وحجم البيانات المعتمد غير كافٍ حتى الآن. تشغيل التدريب قبل اجتياز الموافقات والـ preflight سيكون مخالفًا لبوابات المشروع.

## هـ) التقييم قبل أي إطلاق

1. شغّل مجموعة التقييم المحجوزة كما هي دون إدخال أسئلتها أو إجاباتها إلى بيانات التدريب.
2. احتفظ بالمخرجات الخام والأخطاء مع بصمة checkpoint.
3. قيّم العربية الفصحى والمصرية كلًّا على حدة: الفهم، صحة الإجابة، ترابطها، اتباع التعليمات، وعدم اختلاق المعلومات.
4. اطلب مراجعة بشرية للأجوبة؛ لا تكفي خسارة التدريب أو نجاح تحميل النموذج أو اختبارات Python لإثبات جودة اللغة.
5. قارن checkpoint المرشح بخط الأساس على نفس الأسئلة ونفس شروط التقييم.
6. لا تفعّل `JON2_CHAT_RELEASE_APPROVED` أو `JON2_QUALITY_REVIEW_PASSED` أو `JON2_INFERENCE_TESTED` إلا بعد تحقق الشروط الفعلية وموافقة مالك المشروع.

## و) ما الذي يمكن أتمتته مجانًا؟

| المهمة | المكان |
|---|---|
| فحوصات Python والاختبارات | GitHub Actions |
| مراجعة تغييرات الكود | Pull Request |
| تدقيق بيانات خاصة | Kaggle Notebook |
| تجارب تدريب GPU مؤقتة | Kaggle GPU عند توافر الحصة |
| حفظ checkpoint الخاص | Kaggle Private Dataset أو تخزين خاص |
| مراجعة جودة العربية | تقييم محجوز + مراجعة بشرية |
| تشغيل الموقع الثابت | GitHub Pages |

هذا المسار لا يوفر inference دائمًا على الموقع. لتشغيل نموذج Python بشكل مستمر يحتاج المشروع لاحقًا إلى استضافة Runtime مناسبة؛ لا تدّعِ أن GitHub Pages أو جلسة Kaggle مؤقتة تقوم بهذا الدور.

## قائمة تحقق قبل أول تدريب

- [ ] GPU ظاهر و`torch.cuda.is_available()` يساوي True.
- [ ] بيانات التدريب موجودة في مساحة خاصة.
- [ ] كل ملف تدريبي لديه موافقة مطابقة لبصمة SHA-256 ونطاق الاستخدام.
- [ ] لا توجد بيانات شخصية أو محادثات خاصة غير مصرح بها.
- [ ] تدقيق البيانات وpreflight يسمحان بالتدريب.
- [ ] مجموعة الاختبار المحجوزة منفصلة تمامًا.
- [ ] مسار الإخراج جديد ولا يستبدل checkpoint المصدر.
- [ ] إعدادات resume وحفظ checkpoint مفعّلة.
- [ ] لا توجد أسرار أو أوزان أو corpus خاص داخل GitHub.
- [ ] بوابة المحادثة العامة ما زالت مغلقة حتى مراجعة الجودة البشرية.
